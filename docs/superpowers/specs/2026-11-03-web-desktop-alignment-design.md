# 原 platform 与桌面版功能对齐方案（本机 Web）

日期：2026-11-03（Asia/Shanghai）
状态：用户已确认并授权实施，执行记录见同日实施计划与验收记录。

## 1. 目标与范围

以 `platform` 为交付主体，将 `antenna-draw-desktop` 已实现的业务增强迁入 Web，保持 Vue 3 + Element Plus + ECharts 前端、Node.js + Express 后端和 MATLAB 绘图架构。用户已确认使用场景为“本机启动服务、浏览器访问”。

默认访问地址继续为 `http://127.0.0.1:8000`；前端开发继续使用 Vite。浏览器、Node 服务及 MATLAB 在同一台 Windows 机器上运行，目录选择和打开目录针对服务所在机器。

此次对齐覆盖设置、环境检测、首次引导、任务管理、输出管理、偏好持久化、数据源重定位及诊断。Electron 安装器、窗口菜单、托盘/窗口生命周期、IPC、桌面快捷方式和自动更新不属于 Web 功能对齐范围；桌面版保持独立交付。

“本机 Web”不等于取消后端：MATLAB 启动、目录读写、统计线程、历史记录和结果导出继续由 Node 承担。暂不扩展局域网、多用户、账号或云上传。

- 桌面参考文档：`docs/desktop-v1/release-notes-1.0.0.md`、`hotfix-1.0.1.md`、`baseline.md`。

- 桌面验收记录用于识别已有能力及故障修复，不能代替迁回 Web 后的实际验收。方案梳理阶段未运行构建、MATLAB 或功能回归；实施后的实际结果见同日验收记录。

核心业务已有很高的一致性：`scanner.js`、`plotTypes.js`、`rasterData.js`、`rasterPreview.js`、`renderOptions.js`、`analysisStats.js`、`analysisWorker.js`、`analysisModel.mjs`、`rasterRenderer.js` 及七个 `showrsrp_*.m` 内容相同。

## 4. 实现路线比较

| 路线 | 优点 | 代价与适用性 |
|---|---|---|
| A. 在 platform 按模块迁入业务增强（推荐） | 保留 Web 入口与现有数据，能逐阶段验收和回退 | 需要显式梳理跨模块依赖 |
| B. 整体复制桌面前后端并删除 Electron | 一开始差异较少 | 容易带入 desktopBridge、用户目录、渠道默认值、会话启动假设和安装资源路径 |
| C. 先抽公共包，同时重构两个项目 | 长期减少重复 | 同时影响两个交付物，增加此次范围和回归成本 |

采用 A。阶段内允许迁入桌面版已有的服务工厂和依赖注入结构，但不顺带改变绘图/统计算法，不先做跨项目公共包。对齐完成后再评估公共模块抽取。

## 5. 目标架构与职责

```text
浏览器 Vue
  绘图 / 对比 / 分析 / 设置 / 引导 / 任务记录 / 诊断
                        │ 同源 HTTP /api
Express Web 服务（固定端口，默认 8000）
  设置与偏好 / MATLAB 环境 / 数据源 / 任务 / 预览 / 导出
                        │
  JSON 持久化    任务队列与输出管理    原有 DEM 统计线程
                        │
             Windows 进程监管 → MATLAB
```

- 浏览器只管理交互与展示，不调用 Electron API，不运行 MATLAB，不依赖原生桥。
- `serverApp.js` 负责组装服务，`server.js` 保持 Web 启动入口；服务地址、端口、静态资源和开发代理由 Web 配置决定。
- 将桌面状态模型中可复用的检测、设置逻辑调整为 `appModel.mjs` / `appState.js`，避免 Web 业务依赖 `desktopState`。
- 将桌面 `desktopRoutes.js` 拆成 Web 可读的应用设置/环境/引导路由，保留可复用的 HTTP 契约。
- 维持轮询机制；本轮不引入 WebSocket 或新服务框架。
- 同一本地服务的多个浏览器标签页共享数据源、设置、偏好和任务记录。保存设置前展示当前服务配置，避免误认为是各浏览器独立的设置。

### 5.1 Web 与原生能力的适配

目录继续复用 `/api/fs/drives`、`/api/fs/list` 和 `FolderPicker.vue`。MATLAB 文件选择增加只列出所需文件类型的后端浏览能力，同时支持手工粘贴绝对路径；选择后仍由后端验证文件名、存在性和路径。

导入偏好 JSON 使用浏览器文件选择读取内容，提交经过大小限制和 schema 校验的 JSON，不把浏览器提供的文件名当成服务端绝对路径。独立输出根目录通过现有目录浏览器选择。

“打开结果目录/日志目录”通过本机 Node 服务调用系统打开已校验目录。PNG、ZIP、CSV、诊断文件使用浏览器下载，不提供桌面版专用的保存成功回调。浏览器关闭、刷新或切换页面不会取消后台任务；重新打开后从任务记录继续查看。

### 5.2 MATLAB 检测与任务管理

复用 `matlabEnvironment.js` 和 `check_environment.m` 的真实检测：启动能力、许可相关错误、室内/室外出图、PNG 和 MATLAB 版本。检测支持取消、超时和重试，检测与正式绘图共用一个进程槽位。

只有新建 MATLAB 绘图/重试需要检测就绪；DEM 分析、实时预览、已有图片下载和历史查看可独立使用。绘图提交和重试在前端提示之外，还需后端统一检查环境就绪状态，避免仅依赖按钮禁用。

任务终态统一为 `done / partial / failed / cancelled / timed_out / interrupted`，活动状态为 `queued / running / cancelling`。逐图结果独立记录，部分成功不能显示为全部成功；重试只生成未完成层，并重新验证当前输入与输出配置。

服务重启后将非终态历史标为 `interrupted`，保留成功结果，不自动启动 MATLAB。取消/超时必须确认本次所属进程已退出；不能确认时阻止新绘图，保留恢复证明与可理解的错误，不影响外部 MATLAB。

桌面 1.0.1 的检测中断恢复、恢复后释放对应输出锁一并纳入迁移。Windows 进程监管由 Node 使用，属于后端运行能力，不要求 Electron。需要同步 `processSupervisor.js`、`windowsJobRecovery.js`、`windowsProcessHost.js` 与 C# 源码及对应构建/校验资源，不能只迁任务按钮。

### 5.3 输出与缓存

默认继续写入 `源目录/路损结果图/<任务>/<类型>/`；可选独立根目录，在根下按 sourceId 隔离来源。创建任务时冻结输出路径和设置快照，后续修改输出根不改变已有任务的位置。

迁入完整输出链路：解析与检查路径、跨实例锁、同目录临时 PNG、完整性校验、输入依赖复查、原子发布及元数据写入。导出与历史打开根据任务快照定位，不根据当前输出设置猜测旧文件位置。

历史记录保存原输出路径，并非每次任务都归档一份不可变图片。若后来重绘同一路径，旧任务链接可能指向更新后的文件；若用户删除文件，显示缺失。此次按桌面版的路径历史能力对齐，不承诺结果版本归档。

同步 `prepare_export_figure.m`，清理 MATLAB 工具栏对导出 PNG 的干扰。当前 Web 缓存渲染版本为 3，桌面为 4；迁入出图修复时升级 Web 渲染版本为 4，旧 PNG 保留，但旧缓存不再视为本次渲染已命中。不能一边要求同步修复，一边继续将旧图标为新版本结果。

### 5.4 设置、旧数据与偏好迁移

默认继续使用 `platform/backend/data`，可显式配置独立 Web 数据根；不自动改用 `%LOCALAPPDATA%/AntennaDraw*`，也不读取或修改桌面版用户数据。

数据文件职责：

| 文件 | 内容 |
|---|---|
| `backend/config.json` | Web 启动端口等部署配置；兼容读取旧 MATLAB 配置作为一次迁移来源 |
| `data/settings.json` | MATLAB、输出策略、超时和绘图并发 |
| `data/preferences.json` | 全局色标和分析分档/门限 |
| `data/sources.json` | 现有数据源记录，保留原 sourceId |
| `data/onboarding.json`、`data/environment.json` | 引导完成标志、环境检测证明 |
| `data/jobs/<id>/status.json` | 可查询、可恢复的任务状态 |
| `data/logs/` | 有限大小的运行日志 |

迁移规则：

1. 先备份已有配置与注册表；新设置不存在时，从旧配置提取允许字段，忽略 `_说明` 等描述字段。设置文件存在后不再用旧配置反复覆盖。
2. 保留源数据路径、sourceId 和原始 DEM，不移动、不删除源数据。不将旧 `job.json` 调试文件伪造成有完整逐图结果的历史任务。
3. 将绘图并发明确收敛为 1，与桌面一致；若旧配置大于 1，在迁移报告中显示调整。超时默认 30 分钟，可设置 5～240 分钟。
4. 原 Web 的 `antenna-color-ranges-v1` 与 `antenna-analysis-config-v1` 位于当前浏览器的当前 origin 中。提供“迁入本浏览器旧偏好”的显式入口，校验并预览后写入服务端；只迁可见的旧存储，不承诺读取其他浏览器/端口的数据。
5. 若服务端已有偏好，显示覆盖范围并由用户主动执行导入；不自动用旧 localStorage 覆盖。迁入成功前保留旧存储，导入失败可重试。
6. 新 JSON 存储采用原子写入、备份恢复、schema 校验。较新 schema 禁止旧程序覆盖；坏文件不静默丢弃，页面提示恢复状态。
7. 多标签页保存偏好按指标更新，后端合并字段，避免一个标签页保存 RSRP 时抹掉另一个标签页已保存的 SCR。此次不实现不同标签页自动实时同步。

### 5.5 Web 运行兼容

继续支持现有文档中的 Node.js 20.19+，建议 Node 22 LTS。桌面内置 Node 24，其 `outputPaths.js` 直接使用 `zlib.crc32`；Web 迁移时为 Node 20 提供已验证的 CRC32 实现，并核对其他较新 Node API，不能仅在本机 Node 24 跑通便声称兼容。

Windows 监管辅助程序使用经过构建、哈希校验的资源；开发运行可沿用桌面版的源码构建机制，但正式 Web 交付须提供可追溯的辅助程序构建产物与校验信息。缺失/损坏时明确说明修复方式，不将运行失败隐藏为普通 MATLAB 许可错误。该依赖及 Windows 要求写入 Web 部署说明。

本地监听明确绑定 `127.0.0.1`；修改配置、启动进程、浏览目录等接口采用本地 Host/Origin 检查和同源请求约束，开发代理单独配置。不直接复制 Electron 启动时注入 Cookie 的流程。诊断以限量日志和运行信息为内容，先预览后下载。

保留一键启动/停止；端口统一从配置读取，不再要求同时手改三个文件。端口被占用时验证是否为本平台实例，复用或提示冲突，不按端口直接结束未知进程。停止脚本识别本服务，触发后端任务清理并确认退出；关闭浏览器不会停止服务。

## 6. 分阶段交付

### 阶段一：Web 应用服务与设置基础

交付：可保存的设置页、真实 MATLAB 检测、持久化偏好基础及旧配置迁移。为环境检测先建立进程监管服务，后续绘图任务使用同一实例。

主要文件：`backend/server.js`、`src/config.js`、新增 `serverApp.js`、Web 路由、`jsonStore.js`、`settingsStore.js`、`matlabEnvironment.js`、进程监管及恢复模块、`matlab/check_environment.m`；前端新增应用状态、偏好客户端和 `AppSettings.vue`，补充文件选择。

验收：旧数据源仍可读；原 MATLAB 配置正确迁入；检测能成功、取消、失败后重试；无 MATLAB 仍可分析/预览；保存和重新打开页面一致；Node 20 兼容检查纳入基础验证。

### 阶段二：任务与输出闭环

交付：任务历史、逐图状态、取消、超时、重试、重启中断恢复、两种输出策略及历史导出。

主要文件：`jobQueue.js`、`matlabRunner.js`、新增 `jobStore.js`、`outputPaths.js`，联动 `cache.js`、`routes.js`、`exporter.js`、`openResultsFolder.js`；`plot_dispatch.m`、新增 `prepare_export_figure.m`；前端新增 `jobModel.mjs`、`JobStatus.vue`、`JobHistory.vue`，接入 `SourceSection.vue` 与 `CompareView.vue`。

此阶段作为完整链路迁移，不能只单独替换 runner：新 runner 依赖输出对象、输入签名、进程退出证明和持久化任务记录。

验收：部分失败准确计数；取消/超时只处理所属进程；重启不自动重跑；成功层保留；切换输出根后仍能下载原位置的历史图；预览保存使用同一输出策略；损坏 PNG 不发布为成功；工具栏不再进入新导出图。

### 阶段三：完整 Web 交互与数据迁移

交付：首次引导、可重复添加的合成演示、离线数据源重定位、旧项目导入、旧浏览器偏好迁移、完整下载反馈。

主要文件：`App.vue`、Web 应用状态、`FirstRunWizard.vue`、`FolderPicker.vue`、`PlotView.vue`、`AnalysisView.vue`、`GlobalColorRanges.vue`、`InteractiveFigure.vue`、`colorRanges.js`、`analysisConfig.js`；后端 `sourcesStore.js`、`legacyImport.js`、引导/演示路由。演示生成器调整为项目正式脚本，避免运行资源依赖被忽略的测试目录。

验收：全新浏览器能完成引导；跳过 MATLAB 可进入主界面；源目录搬迁后保持 sourceId 并重新扫描；导入无重复记录；旧色标/门限经主动迁入后生效；设置保存失败不提示成功；浏览器刷新后可从历史找回运行任务。

### 阶段四：运行维护与完整回归

交付：日志预览、诊断下载、受限临时文件清理、可靠启动停止、更新部署文档及完整 Web 验收记录。

主要文件：新增诊断 HTTP 路由、`diagnostics.js`，接入日志；`启动平台.bat`、`停止平台.bat`、`frontend/vite.config.js`、配置示例、README 及可复现的 Web 回归材料。

验收：已有非本平台端口进程不被结束；服务优雅关闭；进程恢复失败有清晰反馈；清理不触碰源 DEM、正式结果与任务历史；诊断 ZIP/JSON 可下载且内容与预览一致；构建与全流程回归通过后形成差异清单闭环。

## 7. 不变的业务口径与验收基线

- 五种绘图：RSRP、DLRSSINR、SCR、ECHORP、BESTSERVER；三种坐标和同批统一范围保持。
- 室内楼层、室外地面/高度层、混合任务、墙线优先级和建筑/基站叠加保持。
- DEM 为 int16 little-endian，`-32768` 无效；连续指标除以 100；室外 DLRSSINR 的 0 无效，室内 0 保留。
- BESTSERVER 为编号绘图，分析页仍只提供四类连续指标。

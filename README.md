# 天线覆盖绘图平台

读取仿真结果，调用 MATLAB 生成室内/室外覆盖图，支持多高度层、结果对比和图片下载。绘图脚本已包含在 `matlab/` 中，部署时复制整个项目目录即可，仿真数据可放在其他位置。

## 1. 部署与启动

本项目是本机 Web 版：浏览器、Node 服务与 MATLAB 在同一台 Windows 机器运行，服务仅监听 `127.0.0.1`。支持设置与首次引导、MATLAB 自动发现/真实检测、可取消和重试的持久任务、输出策略、历史下载、离线数据源重定位、合成演示和诊断。分析、实时预览、已有结果下载无需 MATLAB；正式绘图与重试须先在设置页完成环境检测。

运行环境：Windows、Node.js **20.19+**（建议 22 LTS）、MATLAB（绘图脚本以 R2022a 为兼容基线，需要可用许可）。首次安装依赖需要联网。Node 20 的兼容实现包含 PNG CRC32，不依赖较新 Node 的 `zlib.crc32`；实际验证版本以交付验收记录为准，使用 Node 24 测试不等于已经运行过 Node 20 全流程。

1. 下载或克隆完整项目，双击 **`启动平台.bat`**。首次运行自动安装依赖、构建前端；任一步失败会停止启动。
2. 浏览器默认访问 **http://127.0.0.1:8000**。首次引导可添加合成演示、配置 MATLAB 并运行检测；也可先跳过检测进行分析/预览。
3. 在“设置”中选择或粘贴 MATLAB 可执行文件路径，并完成真实检测。检测会在私有临时目录生成室内/室外小样本，检查启动、许可、绘图及 PNG；支持取消和失败后重试。
4. 停止服务时双击 **`停止平台.bat`**。关闭浏览器或启动提示窗口不会停止服务，也不会取消后台任务。

后端端口统一从 `backend/config.json` 的 `port` 读取（缺省 `8000`），启动、停止和 Vite 代理无需分别修改。端口被占用时，启动器复用同项目已就绪实例；未知监听服务会报冲突，**不会按端口杀进程**。停止器校验项目路径、进程标识及私有实例令牌，经 HTTP 等待任务清理与监听退出；无法证明身份或清理失败时明确报错，不强制结束未知进程。

`backend/config.json` 只负责端口等部署配置；运行中的 MATLAB、输出策略和超时在页面设置。可复制 `backend/config.example.json` 为初始部署配置，但首次引导不要求先手改文件。MATLAB 并发固定 **1**，任务默认超时 **30 分钟**，允许 **5～240 分钟**。端口修改后重启服务；本机配置不随 Git 提交。

### 数据与设置迁移

默认数据根仍为 `backend/data`，不读取或改写桌面版用户目录。需要隔离数据时，在启动前设置绝对路径环境变量 `ANTENNA_WEB_DATA_DIR`；启动和停止须使用相同数据根。数据源注册表保留原 `sourceId` 和原始 DEM 路径，不移动或删除业务源。

首次升级会先备份旧部署配置/注册表，再从旧配置提取允许的 MATLAB、输出与超时字段到 `settings.json`；设置存在后不会被旧配置反复覆盖。旧并发大于 1 时会收敛为 1 并显示迁移提示。设置、偏好和引导状态使用带 schema 校验的 JSON、原子写入及备份恢复；坏文件/较新 schema 会明确提示，避免静默覆盖。

同一本地服务的多个浏览器与标签页共享数据源、设置、偏好和任务记录。全局色标及分析分档/门限保存在服务端 `preferences.json`，按指标合并保存；其他标签页可重新读取，不承诺自动实时同步。设置页提供“迁入本浏览器旧偏好”，先预览再主动导入，只能读取当前浏览器当前 origin 下可见的旧 localStorage；不会自动覆盖服务端偏好，成功前保留旧存储。另支持旧项目/偏好 JSON 的显式导入。

任务状态在 `data/jobs/<id>/status.json`，重启后未完成任务标为 `interrupted`，不会自动重跑。日志在 `data/logs`，启动终端输出在 `data/backend.log`；诊断页提供限量日志预览、下载和受限临时文件清理，不清理源 DEM、正式结果或任务历史。`data/web-instance.json` 包含本机停止令牌，不应公开或随诊断分发。

### Windows 进程监管辅助程序

MATLAB 检测、取消、超时和恢复由后端专属 Windows 进程监管器负责，仅处理本次所属进程，不影响外部 MATLAB。源码为 `backend/src/native/WindowsProcessHost.cs`；源码运行首次使用 Windows PowerShell 的 `Add-Type` 编译到数据目录的进程缓存，并记录源码/二进制 SHA-256 与编译器版本。需要 Windows PowerShell/.NET Framework 可用。

正式 Web 文件交付可先在 Windows 项目根运行：

```powershell
node scripts/build-process-host.cjs
```

该命令从本项目 C# 源码重新构建 `backend/src/native/WindowsProcessHost.exe`、相邻 `.manifest.json`，并写入根目录 `build-info.json`（源码/二进制哈希、编译器、构建时间和 Git revision）。部署时三者一起复制并保留构建记录；也可传入独立暂存目录，之后将产物按相同相对路径装入交付目录。校验用于发现损坏/构建不匹配，不代替代码签名。带 `build-info.json` 的交付环境不会临时重编译；缺失、损坏或隔离时会明确报完整性错误，应从可信交付物修复并检查杀毒隔离记录。

## 2. 绘图时应该打开什么

点击页面中的 **“添加”**，选择**仿真结果文件夹**。平台扫描 `pred` 下所有直接子目录，每个任务目录以自己的 `index.txt` 识别数据；任务名不限于 `0`。没有有效索引的子目录会跳过。

例如文件在：

```text
D:/仿真结果/案例A/pred/任务A/RSRP_1.dem
```

应选择 **`D:/仿真结果/案例A`**。不要选择 `pred`、任务目录、单个 `.dem`、`.ils` 或 MATLAB `.m` 文件，也不要选择已经导出的“路损结果图”目录。

添加后，在左侧室内/室外分组中选择数据源，再选择任务、数据类型与高度层/楼层，点击 **“开始绘图”**。只有一个任务时自动选中。同一数据源同时含室内与室外任务时，会在两个分组中分别显示入口，各入口只列出对应任务；切换任务会保留各任务的选项和绘图进度。新增或删除任务后点击数据源的刷新按钮重新识别。

在“结果对比”页选择至少两个「数据源 · 任务」及它们共同的数据类型，可以比较同一数据源内的不同任务，也可以跨数据源对比。

### 室外结果

```text
案例A/
└─ pred/
   └─ 任务A/               # 任务名可自定义，支持多个并列任务目录
      ├─ index.txt          # 必需：UTM 标记、数据文件名、坐标范围和分辨率
      ├─ RSRP.dem           # 地面数据，按所需类型提供
      ├─ DLRSSINR.dem
      ├─ building1          # 可选：建筑轮廓，无扩展名
      ├─ cells1.txt         # 可选：基站位置
      └─ 10m/
         └─ RSRP.dem        # 10m 高度数据，其他高度同理
```

- `index.txt` 包含以 `UTM` 开头的行时，识别为室外。
- 数据记录格式：`文件名.dem 左边界 右边界 下边界 上边界 分辨率`。
- 高度层来自 `pred/<任务名>/` 下包含对应 `.dem` 的子目录，例如 `10m`、`20m`；直接放在任务目录下的是地面数据。
- 建筑和基站文件放在各自的 `pred/<任务名>/`，该任务的高度层绘图也读取这里的叠加文件。

### 室内结果（常称路损/覆盖结果）

```text
案例B/
├─ pred/
│  └─ 任务B/
│     ├─ index.txt          # 必需：不含 UTM 标记，使用局部米制坐标
│     ├─ RSRP_1.dem         # 1层 RSRP
│     ├─ RSRP_2.dem         # 2层 RSRP，可选
│     └─ DLRSSINR_1.dem
└─ out.txt                 # 可选：墙线；也支持下述其他文件名
```

- `index.txt` 不含 `UTM` 标记时，识别为室内。每条记录可写为 `左 右 下 上 分辨率`，或 `文件名.dem 左 右 下 上 分辨率`。
- 楼层来自文件名后缀：`RSRP_1.dem` → RSRP、1层；没有数字后缀时记为单层。
- 墙线先在当前任务目录 `pred/<任务名>/` 查找，再在所选结果文件夹查找公共墙线；每个目录按 `walls.txt`、`wall.txt`、`building.txt`、文件名含 `floor` 的 `.txt`、文件名含 `wall` 的 `.txt`、`out.txt` 的顺序选择。
- 普通墙线每行四列：`x1 y1 x2 y2`，支持 `%` 注释；也支持“块编号 数量”头后接指定数量的“编号 x1 y1 x2 y2”记录。墙线坐标应与栅格数据一致。

### 支持的数据类型

| 类型 | 室外文件示例 | 室内文件示例 | 含义 |
|---|---|---|---|
| RSRP | `RSRP.dem` | `RSRP_1.dem` | 参考信号接收功率 |
| DLRSSINR | `DLRSSINR.dem` | `DLRSSINR_1.dem` | 下行参考信号信干噪比 |
| SCR | `SCR.dem` | `SCR_1.dem` | 信杂比 |
| ECHORP | `ECHORP.dem` | `ECHORP_1.dem` | 回波接收功率 |
| BESTSERVER | `BESTSERVER.dem` | `BESTSERVER_1.dem` | 最佳服务小区编号 |

`.dem` 为二进制 int16 栅格，`-32768` 表示无效值；功率/信噪比数据按存储值除以 100，小区编号保持整数。各类型按实际文件提供，不要求全部存在。

**RSRP 是接收功率，不是路径损耗本身。** 如果你所说的“路损文件”是 `PathLoss.dem`、`PL.dem` 等其他名称或格式，目前没有对应的绘图类型，不能直接改名为 RSRP 使用；需要先确认数据含义并增加适配。

## 3. 结果保存与常见问题

默认图片保存在源目录旁；设置中也可选独立输出根目录，按 sourceId 隔离来源。示例：

```text
案例A/路损结果图/任务A/RSRP/案例A_任务A_RSRP_10m_绝对坐标.png
案例A/路损结果图/任务B/RSRP/案例A_任务B_RSRP_1层_相对坐标-区域中心.png
```

任务记录冻结输出路径和设置快照，后续切换输出根不会改变已有任务的下载位置。历史是路径记录，**不是不可变图片归档**；同路径重绘后旧任务链接可能指向新图片，文件被删除则显示缺失。`done / partial / failed / cancelled / timed_out / interrupted` 区分全部/部分成功及中断；重试只处理未完成层，成功结果保留。`queued / running / cancelling` 为活动状态。浏览器下载只表示已准备或已发起下载，不承诺文件已落盘。

结果按任务、数据类型分别存放，文件名包含来源、任务名、类型、层与坐标模式；对比范围不同的图追加范围编号。页面支持单张下载、批量 ZIP 导出和打开结果文件夹。顶部按钮打开当前任务的结果目录，类型旁的入口打开该任务对应类型的子目录；ZIP 内按「数据源/任务/类型/图片」组织。

相邻的 `.meta.json` 用于缓存判断，建议随图片一起保留。数据或当前任务的索引、墙线、建筑、基站文件变化后，下次绘图会检查缓存并按需重新生成。

已有 `pred/0` 自动作为任务 `0` 识别。运行 `node backend/scripts/migrate-results.js` 可把旧结果复制到新结构，也会在预览时按需迁移；根据元数据记录的 DEM 路径确定任务归属，保留原文件，不覆盖目标结果。此次同步导出前清理 MATLAB 工具栏的修复，渲染版本升级为 4；旧 PNG 保留，旧版本缓存会在需要时重绘。

- **无法出图**：在设置页检查 MATLAB 路径并重新检测，查看许可/进程监管/任务错误；MATLAB 首次启动可能需要几十秒。
- **没有识别到数据**：确认添加的是包含 `pred/<任务名>/index.txt` 的结果文件夹，索引记录与实际 `.dem` 文件对应。
- **没有墙线或建筑**：确认文件名、存放位置、文件格式及坐标系符合上面的约定。
- **启动失败**：在项目目录手动执行 `node backend/server.js` 查看终端报错，或查看数据根 `backend.log`。未知端口冲突须换端口或自行检查占用服务；平台不会结束该进程。
- **更新代码后页面没变**：重新构建前端后重启服务：`npm --prefix frontend run build`。

### 实时调节色标上下限

「开始绘图」继续调用 MATLAB 生成并保存原图（已有有效缓存则复用）。每张图卡新增「实时调色」入口，进入后首次读取该层的 DEM 数值，后续拖动双端滑块或输入上下限在浏览器内重新着色，不发绘图请求、不重新启动 MATLAB。待绘图的图卡也可以打开交互预览。

- 支持 RSRP、SCR、ECHORP、DLRSSINR 的连续色标，提供恢复默认与按有效数据范围设置；BESTSERVER 为编号数据，不提供连续色标调节。
- 数据低于下限或高于上限时使用端点颜色；无效值保持透明。上下限改变显示，不删除原始数据，也不代表接收/检测门限。
- 预览包含坐标、色标、标题及墙线/建筑/基站叠加，使用当前坐标模式与绘图批次的范围；版式与 MATLAB 原图可能存在差异。
- 原始栅格长边超过 1024 时进行最近邻采样，并在页面标注原尺寸和预览尺寸；有效数据极值按全部原始数据统计。「按数据范围」可能受到极端值影响。
- 「保存当前预览到结果文件夹」按当前输出策略保存画布（默认 `路损结果图/<任务>/<类型>/`），文件名注明「交互预览」和色标上下限，不覆盖 MATLAB 原图；保存的是预览分辨率。也可以直接下载当前预览。
- 原图下载及「导出全部」继续导出 MATLAB 图片；交互窗口重新打开时检查源数据,优先装配已启用的全局指标范围,未启用时使用默认色标。

### 全局色标配置与一键装配

顶部「全局色标配置」可分别保存 RSRP、SCR、ECHORP、DLRSSINR 的范围。单图调色满意后,也可点击「保存并应用为全局 RSRP 范围」等按钮。启用后,画图展示和对比页中所有同指标的图卡使用该范围绘制浏览器预览,不同指标互不影响；图卡接近可视区域才读取栅格,调色本身不调用 MATLAB。

范围与启用状态保存在本地服务中,重新打开浏览器后可读取。停用后恢复 MATLAB 原图展示,保存的范围仍保留,可通过「一键装配已保存范围」再次启用。连接同一本地服务的浏览器共享此配置，不跨机器同步。

单图实时调色继续保留,进入时继承全局范围,单独调整不会自动改动全局配置；「装配全局范围」可随时还原。只有明确点击保存为全局才影响其他图。下载当前调整效果请使用交互窗口内的预览下载/保存按钮；原图下载和 ZIP 导出仍使用 MATLAB 图片。

## 4. 覆盖结果分析

顶部 **“结果分析”** 支持一个数据源、一个任务的多楼层/高度层统计，目前提供 RSRP、DLRSSINR、SCR、ECHORP 四类连续指标。选择任务、指标与层，点击“开始分析”；不需要先生成 MATLAB 图片。

- 连续指标展示各层区间占比 100% 堆叠图、有效点达标率图、统计明细，以及当前层的区间环形图、数值直方图和分档表。
- 可分别编辑各指标分界值与达标门限，点击“应用并保存配置”即时重算，无需重新读取 DEM；配置保存在本地服务，与全局绘图色标互不影响。预置分档仅作分析起点，不代表行业等级标准。
- 当前层选择、统计概览、该层分布图及明细连续展示，层间对比与各层统计表放在其后；点击各层统计表中的行会选择该层并滚动返回当前层概览。
- BESTSERVER 是最佳服务小区编号，当前暂不在“结果分析”提供入口；原有画图、结果对比与底层分类解析仍保留。2026-10-22 检查当前注册数据源的 24 个 BESTSERVER 文件，共 1,026,238 个栅格全部为 `-32768`，未发现有效小区编号。这说明源文件在当前格式约定下没有有效归属结果，具体生成原因需在仿真输出端确认。以后取得有效编号和小区映射，再考虑独立的小区服务归属分析，不能将编号用于功率或信号质量评价。
- 支持统计汇总 CSV、分档明细 CSV（UTF-8 BOM）及各图 PNG 下载，导出内容注明来源、任务、指标、层及当前配置。切换条件后隐藏旧结果，需重新分析；源文件更新后点击分析会校验缓存，新增/删除层可先刷新数据源。

### 统计口径

统计完整 int16 DEM，不使用交互预览的降采样数据。连续指标除以 100，BESTSERVER 保留整数。`-32768` 为无效；室外 DLRSSINR 同时排除 `0`（沿用现有数据约定），室内 DLRSSINR 和其他指标的零值保留。

区间占比与达标率都以**本层有效点数**为分母；另外展示“有效点/全部点”的数据有效率。无效点不直接解释为覆盖失败。区间左闭右开，自动包含最小分界以下与最大分界以上；门限采用 `≥`。均值是 dB/dBm 数值的算术平均，P10、中位数、P90 使用最近秩法。没有有效数据时展示空态，不给出虚假的 0% 达标结论。

估算面积 = 点数 × 分辨率²，属于栅格估算面积；没有目标区域掩膜，不代表精确建筑内面积，不跨层相加为实际覆盖面积或体积。

后端 `POST /api/analysis` 输入 `{sourceId, taskId, dataType, layers}`，返回各层基础统计与完整原始整数频数；单层缺失、空文件或尺寸错误不影响其他层。最多选择 256 层，最多两个工作线程并行处理，内存缓存上限 32 MiB / 64 层，按源文件、索引、范围及规则版本失效。

## 5. 手动运行与检查（可选）

以下命令在项目根目录分别执行：

```powershell
npm --prefix backend ci
npm --prefix frontend ci
npm --prefix frontend run build
node backend/server.js
```
